# 模型审查与写作

先核对：问题边界、假设依据、集合/参数/变量、定义域、量纲、约束、目标、等价表示、性质证明、算法及验证证据。
用情境—模型映射明确每个业务条件落在哪个定义或公式。可退化特例、小实例独立枚举、边界和反例比一次求解成功更有意义。
完整论文写作必须有当前模型 SHA-256 对应的验证文件、作者确认以及支撑定量主张的输入/结果文件。只有设计审批、旧模型报告或不匹配指纹时，停留在审查/格式样例模式。
正文由当前 Codex 按用户授权撰写。事实、数据、数字和引用必须能回查；缺证据时记录缺口，不生成结果。阶段结论与流程说明写到旁置审查报告，不混入正式数学模型正文。
模型审查并不自动运行原项目求解器；需要补验证时，在原模型项目设计明确的 Actions 验证任务，取得证据后再继续。

`review.py` 仅生成章节和证据清点，不提供数学结论。当前 Codex 必须逐式阅读原稿与代码，给出问题条件—定义—约束—目标—算法—证据的对应关系，指出不成立的推导、遗漏的边界及未验证主张。可行性、最优性和泛化结论分别记录论据。验证报告必须包含所验证模型的指纹、方法、独立复核、失败或反例、适用范围及待确认项；报告获作者确认后才进入正文写作。
